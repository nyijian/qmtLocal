# 05 踩坑记录

报错了先在这页搜关键字。每条写：现象 → 原因 → 解决。新踩的坑往对应分类里加。

## 编码

### .env 被 VSCode 存坏

- **现象**：`UnicodeDecodeError: 'utf-8' codec can't decode bytes in position 20-21: invalid continuation byte`，
  出在 `dotenv_lite.load_dotenv()`。
- **原因**：`.env.example` 是 UTF-8，在 VSCode 里改名成 `.env` 再保存。VSCode 被设置成按 GBK 打开，
  UTF-8 中文按 GBK 解出来有落单的字节，保存时变成了 `?`（比如「为」`E4 B8 BA` 变成 `E4 B8 3F`）。
- **解决**：`dotenv_lite` 已改成 UTF-8 解不开就退回 GBK 读，坏掉的只是注释，不影响取值。
  以后用 `copy .env.example .env` 复制，别在 VSCode 里改名。（2026-09-28）

### GBK 脚本 `python xxx.py` 报 `SyntaxError: encoding problem: gbk`

- **原因**：Python 3.6.8 把 GBK 文件当顶层脚本运行时，中文超过 10 行就报这个错；被 import 时没问题。
- **解决**：本地直接运行的脚本一律 UTF-8 带 BOM。详见 [qmt_mock/README.md](../qmt_mock/README.md) 的「文件编码约定」。

### PowerShell 里中文输出乱码

- 终端代码页问题，不是脚本问题。先执行 `$OutputEncoding = [Console]::OutputEncoding = [System.Text.Encoding]::UTF8`。
  用 Python 重定向到文件时设 `$env:PYTHONIOENCODING='utf-8'`。

### `git diff` / GitHub 上 GBK 文件的中文是乱码

- 显示问题，文件本身没坏。

## 桥接服务

### `连不上 QMT 桥 127.0.0.1:58611（[WinError 10061] 由于目标计算机积极拒绝…）`

- **原因**：大QMT 开着，但「桥接服务」策略没在运行，58611 没有程序在监听。
- **解决**：按 [01-环境搭建](01-环境搭建.md#4-在大qmt-里挂桥接服务) 挂上。

### `QMT 桥 127.0.0.1:58611 的端口在，但不回应请求`

- **原因 1**：策略被停了，监听句柄还留在 QMT 进程里（僵尸端口）。常见于在「策略编辑器」里点运行后又停止。
- **原因 2**：策略周期是「日线」这类低频周期，QMT 很少进入 Python，桥的后台线程抢不到时间片。
- **原因 3**：已经收盘。收盘后 QMT 不再驱动策略，桥会停止响应（2026-09-28 15:00 后实测出现）。
- **原因 4**：桥是活的，只是偶发卡了五秒以上。2026-10-20 10:17 碰到过一次：QMT 日志里有这次的「客户端接入」，5 秒后客户端放弃断开，同时段「最近 N 秒进 Python M 次」照常 24 次/10 秒，其它日志也没异常；紧接着 30 次新连接 ping 都在 0.4 秒内回。原因没查到。2026-10-23 09:20 又碰到一次（tick_archive 计划任务，QMT 09:17 刚启动桥、没有别的客户端、交易轮询空闲），两次 ping 共 10 秒都没回；10 秒后重试的连接正常，09:22 手动 ping 都是 0.00 秒。
- **解决**：回「模型交易」把桥接服务那一行重新启动；周期改成「分笔线」；收盘后改用 `--offline` 或 `dat_reader`。原因 4 直接重试。
- **怎么分辨**：看 `userdata\log\XtClient_FormulaOutput_<日期>.log`。有这次的「客户端接入」、进 Python 次数正常 → 原因 4；没有接入记录 → 原因 1；次数很小 → 原因 2。
- 客户端现在连上后最多 ping `VERIFY_ATTEMPTS`（2）次、每次 5 秒，都没回才报这个错，偶发卡顿一般自己就过去了。

### 策略日志里 `execude cmd:  -u "...桥接服务.py"`、`return code:1`

- **原因**：勾了「使用外部python」，QMT 去找一个外部 Python，路径是空的。
- **解决**：策略编辑器右侧「基本信息」里取消勾选。

### 盘中偶尔 `调用 get_full_tick 超时（30.0s）`，午休、尾盘、收盘后最多

- **原因**：桥的后台线程只有在 QMT 进 Python 时才轮得到时间片，原来只靠 handlebar 进，而 handlebar 只在主图来新 tick 时才被调。2026-10-15 QMT 日志（`userdata\log\XtClient_FormulaOutput_<日期>.log` 里桥打的「最近 N 秒被调用 M 次」）显示：平时 3 秒一次；11:30~13:00 一次都没有；14:43 卡了 153 秒；14:57~15:00 收盘集合竞价十几秒一次；15:00 后停。这些时段请求全部超时。
- **解决**：桥接服务 `init` 里用 `ContextInfo.run_time('bridge_timer', '500nMilliSecond', ...)` 注册定时器，按墙钟定时让出时间片（`TIMER_PERIOD`，设 '' 关掉）。注册失败会在日志里说，退回只靠 handlebar。客户端这边别把超时设成 30 秒干等：`t0_sim.py` 单次 8 秒、失败 3 秒后重试，午休和收盘集合竞价不取。
- **排查**：看 QMT 日志里那行频率，某段时间没有这行，或者间隔远大于 10 秒，就是那段时间桥被饿死了。

### `get_market_data_ex(period='tick')` 只有当天的数据，前一天起全是 0 条

- **现象**（2026-10-21 实测）：600366、600436 取当天 tick 有数据（从 09:15 集合竞价开始，盘中什么时候取都给全天）；取 20261020 及更早的任何一天都返回 0 条。本地 `datadir\<市场>\0\<代码>\` 也是空的。
- **补充**（2026-10-23）：`datadir\SH\0\600000\` 下有 `20261015.dat` 这类按日期的文件，桥能读出来，但只有 14:37~15:30 这一段（466 条）——是 QMT 界面当时看过这只票顺手缓存的，不是完整一天，也不能靠它补历史。
- **结论**：tick 历史没法事后补，只能每天收盘前自己存。用 `tools/tick_archive.py`；15:00 后桥不响应，最后一次要在 15:00 前拉成功，收盘集合竞价那一笔可能赶不上。

### 短样本里「全赢」的日内规律，换长样本就亏

- **现象**（2026-10-21）：600366、605208 只有约 40 天 5 分钟线，「高开 ≥1% 开盘卖、挂低 1% 买回」14 次全赢；用 2015 年起的日线复核，600366 同样条件 168 天净 -0.32%。
- **做法**：规则只要是「开盘进场 + 挂单 / 收盘了结」，挂单成不成交只看当天最高最低，用 `.DAT` 日线就能准确回测，样本是分钟线的几十倍。`tools/pattern_tests.py` 末尾的「日线长样本复核」就是这么做的。

### 以为 QMT 本地只有日线，其实 5 分钟线也有好几年

- **现象**（2026-10-21）：`datadir\SH\300\600436.DAT`、`000300.DAT` 有 2023-05 起的 5 分钟线，比桥 `get_market_data_ex` 拉到的（2025 起）还长。
- **用法**：`qmt_bridge.dat_reader.read_bars(code, '5m')`，索引是 K 线结束时刻 `YYYYMMDDHHMMSS`。`\60\` 目录是 1 分钟线（`read_bars(code, '1m')`）。哪只没有，就在 QMT「数据管理」里补 5 分钟 / 1 分钟线。

## 本地日线缓存（.DAT）

### 数据滞后很多天

- **原因**：大QMT 只在你看过某个代码，或者手动「补充数据」之后才刷新缓存，不会每天自动补。
  2026-09-28 时发现全市场缓存停在 08-26，指数停在 04-17。
- **解决**：QMT「数据管理」→「补充数据」→ 沪深A股、日线，补到当天。`tools\local_history.py --gaps` 可以检查。
  `market_overview.py` 发现历史滞后超过 11 天会自动跳过量比，并把均线类指标标成「仅供参考」。

### 读缓存时 `OSError: [Errno 22] Invalid argument`

- **原因**：`datadir\SZ\86400\` 下有 `000001_4002.DAT` 这类带后缀的文件，格式不同，时间戳解出来是负数。
- **解决**：只读 6 位纯数字文件名的（`market_overview.is_a_share` 已处理）。

### 缓存价格是不复权的

- 除权那几天均线会有点偏。看全市场比例影响不大；做个股精确计算要注意。

## Python 环境

### uv / pip 装包超时

- **原因**：这台机器连官方 PyPI 很慢。
- **解决**：`-i https://pypi.tuna.tsinghua.edu.cn/simple`，并设 `UV_HTTP_TIMEOUT=180`。

### 3.13 下 `dat_reader` 报 SyntaxWarning / DeprecationWarning

- 已修（2026-09-28）：文档字符串里的 `\.` 改成 `\\`；`utcfromtimestamp` 改成 `epoch + timedelta`，两个版本都没警告。

## akshare

### 融资融券明细返回空表或 `Length mismatch: Expected axis has 0 elements`

- **原因**：传的日期不是交易日（比如 2026-09-25）。
- **解决**：只传交易日。可以先用 QMT 日线或 `get_trading_dates` 确认。

### 深交所请求报 `ProxyError` / `Remote end closed connection without response`

- **原因 1**：本机开着系统代理（127.0.0.1:10808，环境变量 `http_proxy` 也指向它），requests 默认走代理，经代理访问深交所报 `ProxyError`。
- **原因 2**：深交所有反爬。2026-09-28 连续几分钟每 0.5 秒一次请求，大约两百次后被封，直连也会被直接断开。
- **解决**：`fetch_akshare.py` 默认直连（进程内设 `NO_PROXY=*`，不改系统设置）；深交所请求间隔 3 秒；
  同一类连续失败 5 次自动停下。被封了就过一阵再重跑，已下好的会跳过。
- **另外**：深市两融汇总**不能**用个股明细加总代替——融资买入额对得上，但融资余额差约 0.7%。

### 龙虎榜某个月报 `TypeError`

- **原因**：查询区间里没有交易日（比如 2023-09-29 中秋节到 30 日周六），akshare 没处理空结果。
- **解决**：已改成先用交易日历判断，没有交易日的区间直接跳过。

### 龙虎榜「解读」标签 2025 年口径变了

- **现象**：「实力游资买入/卖出」2024 年还占约 23%，2025 年起变成 0；同期「普通席位买入」从 4% 跳到 20%。
- **原因**：东方财富 2025 年起不再打「实力游资」标签，并入了「普通席位」。
- **影响**：用标签看游资的长期趋势会在 2025 年断层。游资/散户/北向的变化改用 `lhb_yyb`（营业部金额）来看。

### ETF 份额：三个来源口径不一样

- **东方财富 `fund_etf_spot_em` 的「最新份额」不能用**：2026-10-13 盘中实测，同一时刻 510300、588000、512100 是 10-09 的份额，
  513120、513350 却是 10-12 的，口径不齐；而且是 float32，末几位有误差。
- **深交所 `fund_etf_scale_szse` 报 `TypeError: Expected file path name or file-like object, got <class 'bytes'>`**：
  akshare 把响应 bytes 直接传给 `pd.read_excel`，新版 pandas 不认。`fetch_akshare.py` 里自己请求、包成 `BytesIO`。
  深交所只给「当前规模」，没有日期列，盘中查到的是上一交易日收盘份额。
- **上交所 `fund_etf_scale_sse(date)` 查当天（还没公布）报 `KeyError`**，不是空表。已当成「还没出数」处理。
- **QMT `get_instrument_detail` 的 `TotalVolume` 就是份额**，对应 `TradingDay` 那天收盘，跟上交所、深交所官方数逐位一致，
  沪深都有，查 1740 只不到 1 秒。`etf_overview.py` 用的就是它。

### ETF 的 IOPV（实时参考净值）从哪拿

- **QMT tick 和合约信息里都没有 IOPV**：`get_full_tick`、`get_instrument_detail` 返回的字段里找不到。`get_market_data_ex(period='etfiopv')` 不报错，但返回的跟 `tick` 周期一模一样，是 QMT 不认识这个周期、悄悄退回了 tick，别当成 IOPV。
- **真正的接口是大QMT内置的全局函数 `get_etf_iopv(code)`**（见 `D:\国金证券QMT交易端\config\fun.xml`），不在 ContextInfo 上。桥 2026-10-14 起转发它：`xtdata.get_etf_iopv(['510300.SH', ...])`。
- **东方财富备用**：`push2.eastmoney.com/api/qt/ulist.np/get?secids=1.510300,...&fields=f2,f12,f14,f441,f402`，`f441` = IOPV，`f402` = 折价率（正数为折价）。2026-10-14 实测 `ak.fund_etf_spot_em()` 直连也被断开，同一个接口用 curl 能通。
- **收盘后别拿收盘价比当天净值算港股 ETF 的折价**：港股 16:00 才收，净值反映的是 A 股收盘后那一小时，会系统性显示约 1% 的假折价。

### 接口突然报错或字段变了

- **原因**：akshare 是爬网页的，网站改版就会坏。
- **解决**：先 `uv pip install -U akshare` 试最新版；好了就把新版本号写回 `requirements-data.txt`。

## OneDrive 共享数据

### 出现 `summary_szse-机器名.csv` 这种文件

- **原因**：两台机器同时写了同一个文件，OneDrive 没法合并，就把其中一份改名保留下来。
- **解决**：`fetch_akshare.py` 跑完会列出来。核对哪份新（看行数、最后日期），删掉另一份；以后两台别同时跑。

### `fetch_akshare.py` 一开跑就报 `PermissionError: [WinError 5] 拒绝访问`（`last_run.json`）

- **原因**：OneDrive 正在同步 `_sync/last_run.json`，短暂锁住，`os.replace` 失败。事后文件能正常打开。
- **解决**：替换文件统一走 `replace_retry()`（重试 6 次、间隔递增），`save()` 和 `write_last_run()` 都用它。

### 另一台机器读数据很慢或断网读不到

- **原因**：OneDrive「按需下载」，文件只是占位符。
- **解决**：右键 `data` 目录 →「始终保留在此设备上」。

## 大盘统计口径

- **ST 股涨跌停按 5% 算**（`market_overview.ST_LIMIT`）。交易所规则变了改这个常量。
- **全推快照里没有股票名称**，判断 ST 是只对主板里涨跌幅在 ±4%~6% 的股票查名称。离线模式拿不到名称，不统计 ST 的涨跌停。
- **盘中的成交额是截至当前的**，跟历史全天比时按已交易时间线性折算，只是粗估（成交量在一天里是 U 形分布）。

## 做 T 实盘

### get_full_tick 偶尔推一笔成交额放大 100 倍的 tick，VWAP 算成几百上千

- **现象**（2026-10-19）：宁波韵升正常 tick 的 `amount/volume/price` 约 99（volume 单位是手），隔几分钟就冒出一笔约 9900 的，
  下一笔又恢复正常。VWAP 被算成 977，`t0_live.py` 以为价格已经回到均价，误触发止盈，提前买回（这一轮净亏 30 元）。
- **解决**：VWAP 偏离现价超过 10% 的 tick 整笔丢掉（`t0_live.VWAP_DEV_MAX`，`t0_sim.py` 也加了同样的过滤）。
  丢掉时日志里会记「丢掉坏 tick」。

### STOP 文件不能挡平仓

- **现象**：最早的版本里，STOP 把所有委托都挡住了。手上有一半先卖出的仓位时叫停，会卡住买不回来。
- **解决**：STOP 只挡开新的一轮，平仓照常执行。

### `get_full_tick` 一段时间里断断续续给成交额放大 100 倍的快照

- **现象**（2026-10-23）：13:17~14:09 t0_live 每 3 秒取一次 600366、605208 的快照，约两成成交额放大 100 倍，VWAP 算成 987、1138；13:20 手动取、收盘前连取 100 次都正常；同一天 `get_market_data_ex(period='tick')` 存档的 tick 没有一条坏的。10-19 13:58 也出过一笔。原因没查到。
- **影响**：只丢坏 tick 的话，这段时间有仓位时止损不判断。
- **解决**：`t0_live.py` 坏 tick 时有未平仓位照常判断平仓（VWAP 用上一笔正常的），见决策记录 10-23。用 tick 做研究时先过滤 `amount / volume / lastPrice` 不在 50~200 的行。

### 订阅全推 `subscribe_whole_quote(['SH','SZ'])` 推来的不只是股票

- **现象**（2026-10-23 冒烟测试）：两分钟收到 51079 个不同代码，大头是债券、基金、回购（SZ19、SH23、SH24、SZ56 开头……），A 股只占一成左右，约 2800 行/秒。
- **解决**：`market_tick_archive.py` 先按「沪深A股」「京市A股」板块的代码列表订阅，不认再按市场订，回调里按代码过滤。
