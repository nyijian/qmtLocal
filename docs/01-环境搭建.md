# 01 环境搭建

换机器或重建环境时照着做。涉及三样东西：两个 Python 虚拟环境、`.env`、大QMT 里的桥接服务。

## 前提

- 大QMT 装在 `D:\国金证券QMT交易端`，能正常登录。
- Python 3.6.8 基础安装在 `D:\QuantStock\python36`。
- 装了 [uv](https://docs.astral.sh/uv/)（用来建 3.13 环境，uv 会自己下载 Python 3.13）。

## 1. `.venv`：Python 3.6，给策略开发和 qmt_mock 用

要跟大QMT 内置的 Python 完全一致。numpy / pandas / talib 这些包现在几乎没有 py3.6 的
wheel 能 pip 装，所以是**直接从 QMT 安装目录拷过来的**，不是 pip 装的。

```powershell
D:\QuantStock\python36\python.exe -m venv .venv
```

然后按 [qmt_mock/README.md](../qmt_mock/README.md) 里「从QMT拷贝的第三方包」那一节的
PowerShell 脚本，把 numpy 1.19.1 / pandas 0.22.0 / talib 0.4.17 等拷进
`.venv\Lib\site-packages`。验证：

```powershell
.venv\Scripts\python.exe -c "import pandas, numpy, talib; print(pandas.__version__, numpy.__version__, talib.__version__)"
# 应输出 0.22.0 1.19.1 0.4.17
```

VSCode 的默认解释器就是它（`.vscode/settings.json` 里的 `python.defaultInterpreterPath`）。

## 2. `.venv313`：Python 3.13，给数据分析和 akshare 用

依赖清单在 [requirements-data.txt](../requirements-data.txt)，版本是钉死的。
**官方 PyPI 在这台机器上会超时，要走清华镜像：**

```powershell
uv venv .venv313 --python 3.13
$env:UV_HTTP_TIMEOUT='180'
uv pip install --python .venv313\Scripts\python.exe -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements-data.txt
```

验证：

```powershell
.venv313\Scripts\python.exe -c "import akshare, pandas; print(akshare.__version__, pandas.__version__)"
```

`qmt_bridge` 只依赖标准库和 pandas，3.13 下能直接 import，不用额外装东西。

## 3. `.env`：资金账号

```powershell
copy .env.example .env
```

然后编辑 `.env` 填上 `QMT_ACCOUNT_ID`。**用 `copy` 命令复制，不要在 VSCode 里改名**——VSCode
会按 GBK 打开 UTF-8 文件，保存时把中文注释弄坏（见[踩坑记录](05-踩坑记录.md#env-被-vscode-存坏)）。
`.env` 在 `.gitignore` 里，不会被提交。

## 4. 在大QMT 里挂桥接服务

`tools/` 里的实时功能都要靠它。完整步骤和排错在 [qmt_bridge/README.md](../qmt_bridge/README.md)，
要点：

1. 把脚本以 GBK 读出来放进剪贴板：
   ```powershell
   [IO.File]::ReadAllText("D:\QuantStock\qmtLocal\qmt_client_scripts\桥接服务.py", [Text.Encoding]::GetEncoding(936)) | Set-Clipboard
   ```
2. QMT「策略编辑器」→ 新建 Python 策略 → 全选粘贴 → 保存。
3. 右侧「基本信息」里**取消勾选「使用外部python」**。
4. **策略周期选「分笔线」**（日线周期下桥的线程抢不到时间片，请求会大面积超时）。
5. 去「模型交易」→「新建策略交易」→ 选这个策略、选资金账号 → 点「运行」。
   **不要在「策略编辑器」里点运行**，那样停止后会留下僵尸端口。
6. 日志里出现 `[bridge] 已监听 127.0.0.1:58611` 就好了。本机检查：
   ```powershell
   if (Get-NetTCPConnection -State Listen -LocalPort 58611 -ErrorAction SilentlyContinue) { "通了" } else { "还没起" }
   ```

## 6. 本地日线缓存要定期补

`tools/local_history.py`、`market_overview.py` 的均线和量比读的是大QMT 的本地日线缓存，
这份缓存**不会每天自动更新**。定期去 QMT「数据管理」→「补充数据」，选沪深A股、日线，补到当天。
`.venv\Scripts\python.exe tools\local_history.py --gaps` 能看哪些代码滞后了。

缓存保存的是每只股票**从上市到现在的全部日线**，QMT 不会删旧数据。2026-09-29 核对近 5 年（1211 个交易日）：
在市 A 股里 4290 只完整，917 只上市不满 5 年（从上市日起完整），14 只中间有缺口（都是长期停牌的，比如 000670.SZ）。
不复权；分钟线和 tick 基本没有，要用得在「补充数据」里另选周期补。

## 7. 共享数据目录（OneDrive，两台机器共用）

akshare 下载的数据（以后还有因子、报告）放在 OneDrive，两台机器共用一份：

```
C:\Users\nyiji\OneDrive\05_量化策略\data\
├─ README.md      目录说明和共用规则
├─ _sync\         last_run.json：最近一次下载的机器、时间、结果
├─ akshare\       finance\  lhb\  margin\
├─ qmt_export\    从 QMT 导出的数据
├─ factors\       自己算的因子
└─ reports\       报告存档
```

**第二台机器接入：**

1. `git clone https://github.com/nyijian/qmtLocal.git D:\QuantStock\qmtLocal`，按本页第 1~5 步建环境。
2. `.env` 里把 `QMTLOCAL_DATA_DIR` 设成**这台机器上**的 OneDrive 路径（用户名可能不一样）。
3. 在资源管理器里右键 `data` 目录 →「OneDrive」→「始终保留在此设备上」。不设的话文件只是占位符，
   脚本读的时候才逐个下载，断网就读不到。
4. 自己的大QMT「补充数据」补日线（K 线不走 OneDrive）。
5. 跑一次 `.venv313\Scripts\python.exe tools\fetch_akshare.py`，只会补缺的。

**共用规则：** 谁用谁下，但**两台不要同时跑下载器**。开跑时另一台 3 小时内跑过会打印警告；
跑完如果发现 `文件名-机器名.csv` 这种 OneDrive 冲突副本会列出来，核对后删掉多余的。

`QMTLOCAL_DATA_DIR` 没配时，脚本退回到项目里的 `real_data\`，单机也能照常用。
