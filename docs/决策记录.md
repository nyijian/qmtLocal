## 2026-08-28　本地 3.6 环境直接拷贝 QMT 自带的包

- **背景**：策略最终在大QMT 内置的 Python 3.6 里运行，talib 等是针对这个版本预编译的二进制。
- **决定**：`.venv` 用 Python 3.6.8，numpy / pandas / talib 从 `D:\国金证券QMT交易端\bin.x64\Lib\site-packages` 直接拷贝。
- **原因**：py3.6 现在基本没有可 pip 安装的 wheel，拷贝能保证跟 QMT 里完全一致。
- **代价**：重建环境要手动拷贝（脚本在 `qmt_mock/README.md`）。

## 2026-08-28　用 qmt_mock 本地假运行策略

- **决定**：自己实现假的 `ContextInfo`、`passorder`、`get_trade_detail_data`，行情是合成的。
- **原因**：不开 QMT 也能在编辑器里查语法和逻辑错误。
- **代价**：只实现了用到的接口；结果不能用来评估收益。

## 2026-09-23　用桥接服务代替 miniQMT

- **背景**：国金停了 miniQMT。官方 `xtquant.xtdata` 能连上 58600，但取数接口全部返回 `ErrorID 200005`。
- **决定**：在大QMT 里常驻一个策略（`桥接服务.py`），通过 TCP 58611 把 `ContextInfo` 的行情和交易接口转发出来；
  本地的 `qmt_bridge` 跟官方 xtquant 同名同签名。
- **原因**：大QMT 策略运行时是唯一还能拿到行情和交易的地方；接口对齐以后，miniQMT 恢复了只要改 import。
- **代价**：只能在交易时段用；QMT 要一直开着；交易回报靠轮询，最多晚 1 秒。

## 2026-09-23　`ALLOW_ORDER` 默认关

- **决定**：桥接服务默认不允许下单，查询不受影响。
- **原因**：`passorder` 下的是真实账号，没有模拟盘开关。先把查询跑通、确认参数都对，再手动打开。

## 2026-09-23　账号放 `.env`，自己写 `dotenv_lite`

- **决定**：真实账号放 `.env`（不进 git），用仓库里 60 行的 `dotenv_lite` 读，不装 `python-dotenv`。
- **原因**：仓库要传 GitHub，账号不能进提交历史；3.6 环境装包麻烦，这个功能简单到不值得加依赖。

## 2026-09-23　反推 QMT 本地 .DAT 日线格式

- **背景**：收盘后桥用不了，官方 `get_local_data` 也连不上。
- **决定**：直接读 `datadir\<市场>\86400\<代码>.DAT`（`qmt_bridge/dat_reader.py`）。
- **代价**：格式是反推出来的，只验证过日线和沪深两个市场；缓存要手动「补充数据」。

## 2026-09-28　加一个 Python 3.13 环境做数据分析

- **背景**：akshare 和新版 pandas 需要新的 Python，3.6 装不上。
- **决定**：在项目里并排建 `.venv313`（uv 管理，依赖钉在 `requirements-data.txt`），不另开项目。
- **原因**：桥是 TCP 协议，跟 Python 版本无关；实测 `qmt_bridge` 在 3.13 + pandas 3 下直接能用。
  同一个仓库里共用一份 `qmt_bridge`，不会出现两份代码改得不一致。
- **代价**：两个环境共用的代码必须保持 3.6 兼容。

## 2026-09-28　大盘快照：当天走桥，历史读 .DAT

- **决定**：`market_overview.py` 的当天数据用桥的 `get_full_tick` 分批取，均线、量比等历史数据读 .DAT。
- **原因**：桥的 `get_market_data_ex` 会给每只股票挂订阅，全市场五千只太重，而且桥是串行处理请求的。
- **代价**：历史指标的准确性取决于缓存是否及时补过；滞后时脚本会提示。

## 2026-09-28　akshare 数据：财务按报告期批量取，存 CSV

- **决定**：财务用东方财富的全市场报表接口（`stock_yjbb/zcfz/lrb/xjll_em`），按报告期一次取全市场，
  不逐只股票取；龙虎榜按月取；两融明细按交易日取。都存成 UTF-8 带 BOM 的 CSV，放在 `real_data/akshare/`。
- **原因**：按报告期取，3 年只要 48 次请求，逐只取要五千多次，还容易被封 IP。CSV 能直接用 Excel 打开，
  也不用额外装 pyarrow。
- **代价**：四张表只有摘要字段，更细的财务指标要另外逐只取；CSV 读回来时股票代码要指定 `dtype=str`。

## 2026-09-29　共享数据放 OneDrive，谁用谁下

- **决定**：akshare 数据（以及以后的因子、报告）放 `C:\Users\nyiji\OneDrive\05_量化策略\data`，路径写在各机器 `.env` 的
  `QMTLOCAL_DATA_DIR`。本地 `real_data\akshare` 迁过去（1591 个文件逐个核对 SHA256）后删除。
  两台机器谁用谁下，不做写入机器的强制登记（用户选择）；改为开跑时提醒「另一台 3 小时内跑过」、跑完扫描冲突副本。
- **原因**：另一台机器要用同一份数据；OneDrive 已经在两台机器上，最省事。数据量小（约 300 MB，每年多约 60 MB）。
- **不放进 OneDrive**：代码（走 GitHub）、`.venv`（绝对路径，同步过去就坏）、`.env`（账号、每台路径不同）、
  QMT `datadir`（3.5 GB+，各机器自己「补充数据」）。
- **代价**：两台同时跑会出冲突副本，只能靠提醒和人工处理；另一台要把目录设成「始终保留在此设备上」。

## 2026-09-29　数据保留年限：主要数据 5 年，两融个股明细 3 年

- **决定**：日线、财务、龙虎榜、两融汇总保留 5 年；两融个股明细保留 3 年。`fetch_akshare.py` 默认 `--years 5`、`--detail-years 3`。
- **原因**：5 年能覆盖一轮完整的牛熊（2021 年高点以来），Barra 的成长类因子（egro、sgro）也需要 5 年财务数据。
  财务按报告期取、龙虎榜按月取、沪市汇总一次取完，多 2 年只多几十次请求。
  两融个股明细是一天一次请求，深交所还要限速，5 年要多 1000 多次请求、约 1 小时，而且明细主要用来看近期的个股融资动向，3 年够用。
- **日线不用另外下**：QMT 本地缓存本来就保存每只股票从上市到现在的全部日线，近 5 年已经齐全（见 01-环境搭建 §6）。

## 2026-09-28　目录按用途重组；新文档用 UTF-8 带 BOM

- **决定**：根目录的脚本分到 `strategies/`、`tools/`、`tests/`、`logs/`；`main.py` 改名为 `strategies/双均线示例.py`。
  新写的 Markdown 用 UTF-8 带 BOM（旧的两份 README 还是 GBK）。
- **原因**：按「在哪里运行」分目录，编码规则和 Python 版本要求也就跟着目录走，一眼能看出来。
  GBK 的 Markdown 在 GitHub 上会乱码。
- **代价**：`tools/` 里的脚本要自己把项目根目录加进 `sys.path`。
