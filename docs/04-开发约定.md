# 04 开发约定

新建或修改文件前先看这一页。大部分规矩都是踩过坑之后定下来的，原因写在
[05-踩坑记录](05-踩坑记录.md)。

## 1. 文件放哪

| 这个文件…… | 放到 |
|---|---|
| 要贴进大QMT「策略编辑器」当策略跑 | `strategies/` |
| 要在大QMT 里常驻、给外部提供服务 | `qmt_client_scripts/` |
| 在本机命令行直接运行的工具 | `tools/` |
| 会被别的脚本 import 的公共代码 | `qmt_bridge/`（跟 QMT 打交道的）或新建一个包 |
| 自测 / 压测 | `tests/` |
| 两台机器都要用的数据（下载的、算出来的） | 共享数据目录：`.env` 的 `QMTLOCAL_DATA_DIR`（OneDrive）。代码里用 `os.environ.get('QMTLOCAL_DATA_DIR') or real_data` 取根目录 |
| 只在本机用的临时数据 | `real_data/`（不进 git） |
| 运行日志 | `logs/`（不进 git） |
| 文档 | `docs/`，入口是根目录 `README.md` |

`tools/` 和 `tests/` 里的脚本要从项目根目录 import 包，开头照这个写法把根目录加进 `sys.path`：

```python
import os
import sys

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))

from qmt_bridge import xtdata
```

## 2. 文件编码：看文件在哪里运行

| 文件 | 编码 | 首行 | 原因 |
|---|---|---|---|
| `strategies/*`、`qmt_client_scripts/*`（在 QMT 里运行） | **GBK**，无 BOM | `# coding:gbk` | QMT 编辑器只认 GBK，UTF-8 贴进去直接乱码 |
| `tools/*`、`tests/*`、`qmt_bridge/*`（在本机直接运行或被 import） | **UTF-8 带 BOM** | `# coding:utf-8` | GBK 源码中文超过 10 行时，`python xxx.py` 会报 `SyntaxError: encoding problem: gbk` |
| `qmt_mock/*` | GBK（历史原因） | `# coding:gbk` | 只通过 `-m qmt_mock.runner` 走 import，没触发上面那个坑；要直接运行就先转 UTF-8 |
| 新写的 `.md`（`README.md`、`docs/*`、`CLAUDE.md`） | **UTF-8 带 BOM** | — | GitHub 能正常显示；VSCode 看到 BOM 会自动按 UTF-8 打开 |
| 旧的 `qmt_bridge/README.md`、`qmt_mock/README.md` | GBK | — | 历史原因，没转 |
| `.env`、`.env.example`、`requirements-data.txt` | UTF-8（最好带 BOM） | — | `dotenv_lite` 两种都认；BOM 能防止 VSCode 按 GBK 打开 |

**为什么强调「带 BOM」**：`.vscode/settings.json` 把 `files.encoding` 设成了 `gbk`，而且关了自动识别。
没有 BOM 的 UTF-8 文件在 VSCode 里会被当 GBK 打开，一保存中文就坏。有 BOM 的不受影响。

**新建 UTF-8 文件后检查一下**：VSCode 右下角状态栏应该显示 `UTF-8 with BOM`。如果显示 `GBK`，
点它 →「Reopen with Encoding」→ UTF-8，再「Save with Encoding」→ UTF-8 with BOM。

## 3. Python 版本兼容

| 代码 | 要求 |
|---|---|
| `qmt_bridge/`、`qmt_client_scripts/`、`strategies/`、`qmt_mock/`、`tests/` | **必须兼容 Python 3.6** |
| `tools/` 现有脚本 | 保持 3.6 兼容（两个环境都能跑） |
| 只在 `.venv313` 下跑的新脚本（akshare 等） | 随便用新语法；文件开头注明「只在 .venv313 下运行」 |

3.6 下**不能用**：`dataclasses`（3.7）、`from __future__ import annotations`（3.7）、海象运算符 `:=`（3.8）、
`list[int]` / `dict[str, int]` 这种类型标注（3.9）、`X | Y` 类型写法（3.10）、`match`（3.10）、
`str.removeprefix`（3.9）。f-string 可以用（3.6 已支持）。

pandas 也要注意：`.venv` 里是 **pandas 0.22**，没有 `df.attrs`（1.0 才有）、`pd.NA`，`DataFrame.to_markdown` 等也没有。

## 4. 桥接相关

- **本地脚本不直接 import `xtquant`**，统一走 `qmt_bridge`。它跟官方接口同名同签名，
  以后 miniQMT 恢复了只要改 import 这一行。
- **全市场的数据不要走桥取历史**：当天数据用 `get_full_tick` 分批取，历史用 `dat_reader`。
- **`ALLOW_ORDER` 默认保持 `False`**，不要顺手改成默认 True。
- 改了 `桥接服务.py` 或 `qmt_bridge/` 之后跑 `tests\桥接自测.py`；改了线程、队列、连接逻辑再加跑 `tests\桥接压测.py`。
  改完服务端要**重新粘贴进 QMT 并重新运行**才生效。

## 5. 机密信息

资金账号等真实值只放 `.env`（不进 git），代码里用 `os.environ.get('QMT_ACCOUNT_ID')` 读。
新增配置项时同时在 `.env.example` 里加上键名和注释，但不写真实值。
