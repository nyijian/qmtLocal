## 四条数据来源，各管什么

| 来源 | 拿什么 | 什么时候能用 | 注意 |
|---|---|---|---|
| **桥接服务**（`qmt_bridge.xtdata` / `xttrader`） | 实时 tick、全推快照、日线、板块成分、持仓、委托、成交、下单 | 大QMT 开着、桥接服务在「模型交易」里运行，**交易时段内** | 收盘后 QMT 不再驱动策略，桥会不回应。全市场历史不要走桥（见下） |
| **本地 .DAT 缓存**（`qmt_bridge.dat_reader`） | 日线 OHLCV、昨收 | 随时，不需要 QMT 开着 | 不自动更新，要手动「补充数据」；不复权 |
| **akshare** | 财务报表、龙虎榜、融资融券明细和汇总 | 随时（要联网） | 爬网页，接口可能随网站改版失效；两融明细只有交易日有数据 |
| **qmt_mock** | 合成的随机游走行情 | 随时 | 只用来跑通代码逻辑，**不能评估收益** |

## 两台机器怎么共用数据

| 数据 | 放哪 | 怎么同步 |
|---|---|---|
| 代码 | `D:\QuantStock\qmtLocal` | GitHub |
| K 线（日线等） | 各机器自己的 QMT `datadir` | 不同步，各自「补充数据」 |
| akshare 下载的数据、以后的因子和报告 | `C:\Users\nyiji\OneDrive\05_量化策略\data`（`.env` 的 `QMTLOCAL_DATA_DIR`） | OneDrive |
| `.venv`、`.venv313`、`.env` | 各机器本地 | 不同步，各自建 |

OneDrive 里的数据谁用谁下，但两台不要同时跑下载器，否则会出冲突副本。规则和目录说明在 OneDrive `data\README.md`。

## 为什么全市场历史不走桥

桥接服务端调 `get_market_data_ex` 时带 `subscribe=True`，全市场五千只一起取，相当于在 QMT 里
挂五千个订阅；而且桥的所有请求在一个线程上串行执行，一个大请求会把其他调用全堵住。
所以 `market_overview.py` 的做法是：**当天数据走桥的 `get_full_tick`（一次一批，很快），
历史数据读 .DAT 缓存**。

## 桥接协议速览

单条 TCP 连接，一行一个 JSON：

```
请求  {"id": 1, "func": "get_full_tick", "kwargs": {"code_list": [...]}}
响应  {"id": 1, "ok": true, "ret": {...}}
推送  {"push": 7, "data": {...}}          订阅号由客户端分配
```

服务端只认白名单函数、只监听 127.0.0.1。下单受 `ALLOW_ORDER` 开关控制，默认关。
协议细节、线程模型、设计上不能改的地方都在 [qmt_bridge/README.md](../qmt_bridge/README.md)。
